# 逐字稿清洗（清）

输入一个装满 `.md` 逐字稿的文件夹 → 输出清洗后的同一批文件 + 备份 + 校验报告。

**铁律：只修错，不润色。** 不删口语、不改语序、不改语义、不合并观点。判断不了的一律进「存疑清单」，不猜着改。

## 环境事实（直接用，不要重新探索）

```bash
PY=$(ls ~/.workbuddy/binaries/python/envs/default/bin/python 2>/dev/null || command -v python3)
TOOLKIT=~/.workbuddy/skills/transcript-cleanup/scripts/toolkit.py
```

若 venv 不存在，先建（或直接用系统 python3，本工具零第三方依赖）：
`~/.workbuddy/binaries/python/versions/3.13.12/bin/python3 -m venv ~/.workbuddy/binaries/python/envs/default`

## 标准流程（六步，顺序不可换）

### 1. 扫描分类
```bash
$PY $TOOLKIT scan "<逐字稿目录>" --json /tmp/scan.json
```
输出：正常稿 / 歌词误转写 / 极短稿 / 无标题 / 巨段稿 / 碎片稿 的分类与统计。
**先看分类结果再动手**——歌词误转写的文件（正文是背景音乐歌词、中文占比极低）不要按逐字稿改，只加一行说明注释。

### 2. 备份（动手前必做）
```bash
$PY $TOOLKIT backup "<逐字稿目录>"
```
备份落在同级 `备份_原始逐字稿_YYYYMMDD/<目录名>/`。已存在则自动跳过，不覆盖。

### 3. 收集证据，再定词典
**不要凭印象建词典。** 先跑词频与上下文扫描，把疑似误转词连同前后文打出来看：

**本系列（AI 科技博主）已沉淀实测对照表**：`references/ai-niche-asr-errors.md`（含工具名、同音错别字、词中句号高频型、白名单与误报说明）。**先查表，再建词典**——表里是已验证的先验清单，仍需逐处看上下文确认。

```bash
$PY $TOOLKIT qa "<逐字稿目录>" --terms /tmp/terms.json   # terms.json = {"白叶":0,"艺人公司":0,...}
```

常见错误类型（本项目实测的分布）：

| 类型 | 例子 | 判断依据 |
|---|---|---|
| 人名/自称 | 白叶、白野、白夜 → **白也** | 与标题、文件名、作者自称互校 |
| 平台业务词 | 艺人公司 → **一人公司** | 标签里写着 `#一人公司`，全语料 85 处一致 |
| 业务术语 | 配偶/配包/陪宝/培保 → **陪跑**；金准 → **精准**；高边写 → **高变现**；线练营 → **线下营** | 上下文语义 + 同篇其他处正确写法 |
| 工具名 | 口袋 / kexs / codedexx → **Codex**；cos → **Coze**；cloud → **Claude**；scale → **skill**；飞鼠 → **飞书** | 前后文在讲什么工具 |
| ASR 误插句号 | 「思。想」「卡。点」「产。品」「因。为」 | `qa` 自动检出，见第 5 步 |
| ASCII 标点 | `OK, ` → `OK，`、`Hello, ` → `Hello，` | 无歧义，可直接全量替换 |
| 大小写 | `ai` → **AI**、`codex` → **Codex**、`mvp` → **MVP**、`sop` → **SOP** | 英文 token 全量统计后统一 |

**高风险改法**：一词多义必须看全文再定。实测中「壳子 → 客资」是因为前后在讲获客数量，「沉浸 → 陈金」是因为前文在说「陈金是典型的强销售型公司」——这类必须读全文，不能靠词表猜。

### 4. 应用规则
```bash
$PY $TOOLKIT apply "<目录>" --rules /tmp/rules.json
```
规则文件格式：
```json
{
  "literal": [["艺人公司", "一人公司"], ["陪宝", "陪跑"]],
  "regex":   [["(?<![A-Za-z])ai(?![A-Za-z])", "AI"], ["指挥扣。\\s*的人", "指挥AI的人"]],
  "review":  ["『壳子』疑似『客资』，已在 002 确认，其余处待核"]
}
```
`review` 里的只打印不替换。每轮替换都会输出「文件 → 命中规则 ×次数」的日志，**留档写进报告**。

正则注意：上一轮重分段后文本里可能夹着空格/换行，跨断点的匹配一律写成 `。\\s*` 这类容错形式，否则会漏命中（本项目踩过两次）。

### 5. 重分段
```bash
$PY $TOOLKIT repara "<目录>"          # 默认 180~380 字/段，巨段阈值 1200 字
```
处理两种 ASR 病态：
- **整篇一大段**（最长见 3555 字）→ 按句号边界重新切段
- **一句一段的碎片稿** → 先合并再切段

切段边界优先落在句末标点；单段超过 `max×1.6` 时在逗号处二次切分。**只在标点处切，绝不在词中间切。**

### 6. 质检（必须跑，跑到 0 问题或问题全部有解释）
```bash
$PY $TOOLKIT qa "<目录>" --terms /tmp/terms.json
$PY $TOOLKIT report "<目录>" --backup "<备份目录>"
```
`qa` 检查项：无 H1 / 结尾无换行 / 残留 `**标题：**` 行 / 词中句号 / 超长段 / 弱开头段 / 残留误转词。
`report` 输出改动文件数、逐文件字数变化、改名与新增文件。

**误报是正常的**：对话实录里的「对，」「哇，」「哈喽，」是真实口语，不是词中句号。这类把词加进 toolkit 的 `ORDINAL_OK` 白名单，而不是去改正文。目标是「问题数 = 0 或每条都能解释」。

### 7. 生成校验报告
命名 `校验报告_<博主名>_v1.md`，放在博主目录的同级；必须含：修改文件数/总数、错别字修正分类清单（含次数）、格式统一项、重分段统计（段数、平均段长）、特殊文件处理说明、**存疑清单**（无法确证、保留原样的项，逐条写清原因）、备份位置。版式参照 `dontbesilent 相似博主/校验报告_清华白也_v1.md` 与 `校验报告_柱子哥TzFilm_v1.md`。

## 红线

- 不确定的词 → 进存疑清单，**不改**。宁可留一个可疑词，不可改错一个词。
- 不因为「读起来更顺」而调整语序、删重复、补主语——那是润色。
- 口播里的重复（「我我」「就是就是」）属真实口语，**保留**。
- 歌词/纯音乐误转写的文件：加注释说明、保留原样，不要强行当逐字稿清洗。
- 改文件名只做**必要**修正（如文件名里混进换行符），不动标题语义。

## 输出物清单

1. 清洗后的逐字稿文件夹（原地更新）
2. `备份_原始逐字稿_YYYYMMDD/<目录名>/`（回滚用）
3. `<项目>_校验报告_v1.md`
4. 规则文件 `/tmp/rules.json` 与改动日志（报告附件）
